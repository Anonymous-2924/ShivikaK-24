# Boardroom — a dynamic CEO simulation game

Run a company industry-by-industry. Make strategic decisions and watch **every
department** react in real time — cash, reputation, performance, and the
morale/performance of each team. Colorful, animated, and fully local (no server,
no accounts).

This repository currently contains **Phase 1**: the complete game engine + UI,
fully playable, with **one industry (Pharmaceuticals)** and a small set of
placeholder scenarios so you can feel the game immediately. Phase 2 (generating
~200 scenarios per industry) is driven interactively later — see
[Adding content](#adding-a-new-industry-or-scenarios).

---

## Quick start (web app)

```bash
npm install
npm run dev
```

Open the printed URL (default http://localhost:5173). That's the whole game.

Production build + local preview:

```bash
npm run build      # type-checks, then builds to dist/
npm run preview    # serves the built app
```

### Balance-test tool

Simulate thousands of random playthroughs to spot broken or overpowered
scenarios (flags strictly-dominant options, unreachable scenarios, fired rates,
score/grade spread):

```bash
npm run sim              # default industry, 2000 runs
npm run sim pharma 5000  # specific industry + run count
```

## Desktop app (Tauri)

The desktop wrapper is configured under `src-tauri/` (Tauri 2).

```bash
npm run tauri dev     # run the desktop app in dev
npm run tauri build   # build native installers
```

**Honest note about this environment:** Tauri builds need your OS's native
webview libraries. On Linux that's `webkit2gtk` (4.1) + related packages; on
macOS/Windows the system webview is already present. I built and verified the
**web app** here, but I could **not** verify the Tauri build in the cloud
container it was developed in because those system libraries weren't installed.
On your own machine, install the
[Tauri prerequisites](https://tauri.app/start/prerequisites/) first; then the
two commands above should work. If Tauri gives you trouble, the web app is
fully playable on its own, and Electron would be a straightforward fallback.

Placeholder app icons live in `src-tauri/icons/` (generated by
`node scripts/genIcons.mjs`). For real icons plus `.ico`/`.icns`, run
`npm run tauri icon path/to/1024.png`.

## How the game works

- **Pick an industry** → the game loads that industry's profile + scenario bank.
- Each **quarter** presents a fixed number of decisions (configurable per
  industry). After the last one, a **Quarter Review** summarizes what changed.
- The game runs until you're **FIRED** (see below) or you reach the industry's
  max quarter, then shows a final **Score**, letter grade, and wrap-up.
- **Score** is a weighted blend of cash, reputation, company performance, and
  average department morale (see `src/engine/scoring.ts`).

### Scenario selection — buckets + shuffle + conditions

Every scenario has a **bucket**: `early | growth | crisis | endgame |
bankruptcy`. The engine picks from the bucket appropriate to the current
quarter/company state, **shuffled**, so order and selection differ each run —
but coherence holds via **flags** and **metric conditions** on prerequisites
(e.g. a scenario can require an earlier decision set `self_funded_trial`, or that
`cash < 20000`). Scenarios never repeat within a playthrough.
See `src/engine/scenarioSelection.ts`.

### Bankruptcy, second chance & "You're Fired"

Going negative on cash does **not** instantly end the game. The engine tracks
`bankruptcyCount`:

1. **First time cash < 0 → Recovery Mode.** The engine looks in the
   `bankruptcy` scenario bucket for lifelines whose prerequisites match the
   **current** company state. Availability is **state-gated**:
   - *Bank loan* — needs reputation ≥ a threshold.
   - *Emergency equity raise* — needs performance ≥ a threshold; dilutes
     ownership (reputation hit + reduced final-score multiplier).
   - *Fire-sale of assets* — usually available; heavy performance/morale hit.
   - If **at least one** lifeline is available, a dramatic **Crisis screen**
     shows them with their honest consequences; you pick one, take the hit, get
     the cash, and play continues (`used_second_chance` flag set).
   - If **no** lifeline's prerequisites are met, you go **straight to Fired**
     with a specific explanation of why there's no way out.
2. **Second time cash < 0 (or no lifeline was available) → FIRED.** A theatrical,
   comedic roast screen. No third chance.

All lifelines live in `content/scenarios/<industry>/` tagged
`"bucket": "bankruptcy"`, so each industry defines its own — and some states
legitimately have none.

### Advisors

Each department has an advisor with an **expressive portrait** (happy / neutral
/ worried / angry, chosen from current morale + how the scenario treats them).
Two advice modes:

- **Built-in (default, offline):** rule-based — each advisor recommends the
  option that best serves its department, in persona-flavored text. No key
  needed.
- **Live AI (optional):** if you set an OpenAI API key in Settings, advice is
  generated in-character via the OpenAI API. It **gracefully falls back** to
  built-in if the key is missing, invalid, rate-limited, or the call fails.

Portraits are procedural SVG by default; drop in real art later via
`content/characters/<industry>/` (see that folder's README).

## Where to put the OpenAI API key

Open **Settings** (gear icon on the title screen or during a game):

- Paste your key into the **OpenAI API key** field and **Save** (or **Test
  connection** to validate it).
- Switch **Advisor advice** to **Live AI**.
- Pick a model (defaults to a cheap, fast one — `gpt-4o-mini`; verify current
  model names in your OpenAI dashboard).

The key is stored **locally in your browser only** (`localStorage`), is never
committed, and is sent **only** to `api.openai.com`. The key is **optional** —
the game is fully playable without it. OpenAI API usage may incur costs on your
account.

## Architecture — content separated from code

```
src/engine/        industry-agnostic game logic (metrics, selection, scoring,
                   bankruptcy, advisors, optional OpenAI)
src/store/         Zustand store — screen flow + settings + local persistence
src/ui/            React components + screens
content/industries/<id>.json          industry profile
content/scenarios/<industry>/*.json    scenario files
content/characters/<industry>/         advisor portrait art (optional)
scripts/           icon generator + balance test
src-tauri/         desktop wrapper (Tauri 2)
```

A content loader (`src/engine/contentLoader.ts`) scans `content/` at startup via
Vite's `import.meta.glob` and registers whatever industries/scenarios exist.
**Adding an industry = dropping in files. No engine code changes.**

## Adding a new industry or scenarios

**Phase 2 workflow (interactive):** ask for an industry (e.g. "generate
scenarios for FMCG"). You'll get a human-readable markdown document to review,
batch by batch. Only when you say "add it to the backend" are the JSON files
written into `content/` so the game loads them.

### Industry profile (`content/industries/<id>.json`)

See `content/industries/pharma.json` for a complete example: `id`, `name`,
`icon`, `tagline`, `theme` (primary/accent/warn colors), `startingState`
(cash/reputation/performance), `departments` (each with
`startPerformance`/`startMorale`), `advisors`, `quartersPerGame`,
`decisionsPerQuarter`.

> Note: the Pharma placeholder is tuned to a **5-quarter / 2-decision** arc so
> the ~10-scenario placeholder bank fills a full game end-to-end. With a larger
> scenario bank (Phase 2), bump `quartersPerGame`/`decisionsPerQuarter` back up
> (e.g. 12 / 3) — the engine honors whatever the profile specifies.

### Scenario template (`content/scenarios/<industry>/*.json`)

Each scenario specifies effects on **every** department of that industry (use 0
where unaffected). See `content/scenarios/pharma/pharma_early_001.json` for the
canonical shape:

- `id`, `industry`, `bucket`, `tag`, `tagType`, `title`, `situation`
- `prerequisites`: `minQuarter`/`maxQuarter`, `requiresFlags`, `excludesFlags`,
  `metricConditions` (`{metric, op, value}`)
- `options[]`: `label`, `description`, `risk`, `cashChange`, `effects`
  (`company` + per-`departments`), optional `setsFlags`, `outcomeText`, and
  optional `scoreMultiplierDelta` (used by lifelines to dilute the final score).

Rules of thumb: 2–4 options, a range of risk levels, numbers balanced (no
strictly-dominant option — the balance test flags these), effects cover every
department, and a few multi-step storylines via flags. `bankruptcy`-bucket
lifelines typically have a **positive** `cashChange` and prerequisites that gate
availability, and must always carry an honest downside.

## Save / load

The game auto-saves to `localStorage` after every step. "Continue Game" appears
on the title screen when a save exists; "Try Again" / "Play Again" / the ✕ quit
button start fresh.
